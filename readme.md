# EnergyTrace Live

A Python-based tool to automate **Texas Instruments EnergyTrace** measurements using TI `stune`, capture current consumption from a TI LaunchPad/XDS110, and display the data in real time.

The project is designed to work on **Windows** and **native Linux** when a valid Code Composer Studio installation and XDS110 debug probe are available.

## Overview

The project uses two main scripts:

```text
run_energytrace_live.py
plot_energytrace_live.py
```

`run_energytrace_live.py` is the main runner. It resolves the CCS/stune path, creates the output folders, starts EnergyTrace, launches the live plot, monitors errors, and stops the capture when requested.

`plot_energytrace_live.py` monitors the CSV files generated by `stune`, plots current in real time, and calculates power and energy internally.

The scripts can be placed in any directory, as long as both files are kept together in the same folder.

---

## Features

- Runs TI `stune` automatically.
- Supports Windows and native Linux.
- Supports indefinite captures with `--duration 0`.
- Opens a real-time current plot using Matplotlib/Qt.
- Calculates power and accumulated energy internally.
- Uses raw data for energy, average, min, max, and interval analysis.
- Uses downsampling only for plotting performance.
- Allows interactive plot analysis:
  - total consumption;
  - selected interval consumption;
  - point inspection;
  - current-band analysis.
- Stores CSV files, logs, and generated `stune` command files in timestamped output folders.
- Accepts CCS path, target configuration, device, duration, window, refresh rate, and EnergyTrace mode from the command line.

## Requirements

### Software

- Python 3.8 or newer.
- Texas Instruments Code Composer Studio (it was tested with CCS 12.81, 20.51 and 21.00).
- TI `stune`, installed with CCS.
- TI LaunchPad/XDS110 with EnergyTrace support.
- A valid `.ccxml` target configuration file.

### Python Packages

Install the required Python packages:

```bash
pip install numpy pandas matplotlib PyQt6
```

`PyQt6` is required because the live plot uses the Matplotlib `QtAgg` backend.


## Installation

### Windows

Install Code Composer Studio normally.

Then install the Python dependencies:

```bat
py -m pip install numpy pandas matplotlib PyQt6
```

Recommended default CCS location:

```text
C:\ti\ccs2051
```

The runner accepts either:

```text
C:\ti\ccs2051
C:\ti\ccs2051\ccs
```

### Linux

Install CCS for Linux.

Recommended installation location:

```text
/home/<user>/ti/ccs2051
```

Install Python dependencies using a virtual environment:

```bash
cd ~/energytrace-live

python3 -m venv .venv
source .venv/bin/activate

pip install numpy pandas matplotlib PyQt6
```

Install the Linux USB dependency:

```bash
sudo apt update
sudo apt install libusb-0.1-4
```

Run the CCS driver script:

```bash
sudo "$HOME/ti/ccs2051/ccs/install_scripts/install_drivers.sh"
```

Reconnect the LaunchPad after installing the drivers.

## Configuration

### CCS Path

The `--ccs` argument points to the CCS installation.

On Windows, both formats are accepted:

```text
C:\ti\ccs2051
C:\ti\ccs2051\ccs
```

On Linux, both formats are accepted:

```text
~/ti/ccs2051
~/ti/ccs2051/ccs
```

The runner resolves the internal `ccs_base` folder automatically.

### Target Configuration

The `--config` or `--target-config` argument points to the `.ccxml` target configuration file.

Example:

```text
CC1352P1F3.ccxml
```

The actual target is mainly defined by the `.ccxml` file. Changing only `--device` may not be enough to change the real target used by EnergyTrace.

### Device Name

The `--device` argument is passed to `stune`.

For CC1352 LaunchPad measurements, the typical value is:

```text
CC1352
```

Make sure `--device` and `--config` refer to the same hardware target.

## Command-Line Parameters

| Parameter | Description |
|---|---|
| `--ccs` | Path to the CCS installation folder. It can point to the CCS root or directly to the `ccs` folder. |
| `--config`, `--target-config` | Path to the `.ccxml` target configuration file. |
| `--device` | Device name passed to `stune`, for example `CC1352`. |
| `--voltage` | Fallback voltage used only if the EnergyTrace CSV does not contain voltage data. |
| `--battery-capacity` | Battery capacity in mAh used to estimate battery lifetime from the measured average current. |
| `--no-plot` | Set to `1` to disable the live plot while keeping capture and analysis enabled. Default: `0`. |
| `--duration` | Capture duration in milliseconds. Use `0` for indefinite capture. |
| `--downsample` | Downsample window in milliseconds used only for plotting. |
| `--refresh` | Live plot refresh time in milliseconds. |
| `--window` | Visible plot window in seconds. Use `0` to show the full capture. |
| `--max-points` | Maximum number of points displayed in the live plot. |
| `--et-mode` | EnergyTrace mode passed to `stune`. Usually `et`, the `et++` mode may not work for some devices. |

Typical default values:

```python
DEFAULT_DEVICE = "CC1352"
DEFAULT_VOLTAGE = 3.3
DEFAULT_BATTERY_CAPACITY_MAH = 0.0
DEFAULT_NO_PLOT = 0
DEFAULT_DURATION_MS = 0.0
DEFAULT_DOWNSAMPLE_MS = 0.01
DEFAULT_REFRESH_MS = 10
DEFAULT_WINDOW_S = 0.0
DEFAULT_MAX_POINTS = 2000
DEFAULT_ET_MODE = "et"
```

The voltage value passed through `--voltage` is only used as a fallback. If the EnergyTrace CSV contains a voltage column, the voltage from the CSV is used instead.

The sample frequency parameter is not used by this program because some devices use a fixed EnergyTrace sampling rate.

## Warm-up Routine

The runner performs short warm-up captures before the real acquisition.

This helps reduce cases where EnergyTrace reports:

```text
BAD DATA DETECTED
```

after a previous indefinite capture.

If `BAD DATA DETECTED` still appears, try to disconnect and reconnect the LaunchPad.

## Live Plot

The live plot displays current consumption in real time.

The plot shows only current, but voltage, power, and energy are still calculated internally.

### Controls

| Action | Description |
|---|---|
| `q` or `Esc` | Stops the EnergyTrace capture and keeps the plot open. |
| `t` | Prints total consumption from the beginning up to the current time. |
| Right click | Prints current, power, and accumulated energy at the nearest point. |
| Left click + drag | Selects an interval and prints interval statistics. |
| Close window | Exits the live plot. |

### Terminal Output

During acquisition, the live plot prints an updating status line:

```text
Pts=125000 | t=1.25s | I=5.620mA | Iavg=5.604mA | E=23.105mJ | Pavg=18.493mW
```

| Field | Meaning |
|---|---|
| `Pts` | Number of processed points. |
| `t` | Current capture time. |
| `I` | Current at the latest point. |
| `Iavg` | Average current since the beginning. |
| `E` | Accumulated energy since the beginning. |
| `Pavg` | Average power since the beginning. |

### Interval Analysis

Selecting an interval prints a detailed summary:

```text
=========================================================
INTERVAL
=========================================================
Start:                      0.000004 s
End:                        10.047180 s
Duration:                   10.047176 s

Voltage
  Mean:                     3.300000 V

Current
  Mean:                     3.166208 mA
  Min:                      1.163987 mA
  Max:                      20.081163 mA

Power
  Mean:                     10.448486 mW
  Min:                      3.841157 mW

  Energy Start:             0.000000 mJ
  Energy End:               104.977774 mJ
```

## Output Files

The raw EnergyTrace CSV is saved in:

```text
out/YYYYMMDD_HHMMSS/csv/energytrace_YYYYMMDD_HHMMSS.csv
```

The main `stune` log is saved in:

```text
out/YYYYMMDD_HHMMSS/log/stune_log_YYYYMMDD_HHMMSS.txt
```

The warm-up log is saved in:

```text
out/YYYYMMDD_HHMMSS/log/stune_warmup_log_YYYYMMDD_HHMMSS.txt
```

Generated `stune` command files are saved in:

```text
out/YYYYMMDD_HHMMSS/cmd/
```

The live plot does not generate processed CSV files by default. It displays the real-time graph and prints calculated results in the terminal.

## Notes About Sampling and Calculations

EnergyTrace CSV current values are interpreted as nanoamps and converted to amps internally:

```python
current_A = current_nA * 1e-9
```

Voltage is read from the CSV when available. If the CSV has no voltage column, the value passed through `--voltage` is used as fallback.

Power is calculated as:

```python
power_W = voltage_V * current_A
```

Energy is calculated by numerical integration of power over time.

Downsampling is used only for plotting performance. Raw data should be used for energy, average, min, max, and interval calculations.

The estimated battery lifetime is calculated by:

```python
lifetime_h = battery_capacity_mAh / avg_current_mA
```

## Notes About CCS 20 and CCS 12

The EnergyTrace feature in CCS 20 requires an active debug connection to the target device. Therefore, the measured current and power may be higher than those obtained with EnergyTrace Live, since the debug interface and related circuitry can contribute to the overall power consumption.

Older CCS versions (e.g., CCS v12.x) provide an EnergyTrace implementation that can operate without an active debug session, resulting in measurements that are expected to be closer to those obtained with EnergyTrace Live.

## Common Issues

### Unable to load `ccxmlsetup.dll`

This usually means the CCS/stune environment paths are not available.

Check that the `--ccs` path points to a valid CCS installation.

The runner should add these paths automatically:

```text
ccs_base\DebugServer\bin
ccs_base\common\bin
ccs_base\common\uscif
ccs_base\common\uscif\xds110
```

### Unable to load `libccxmlsetup.so`

This means the Linux `stune` executable could not find the required CCS shared libraries.

The runner should set `LD_LIBRARY_PATH` automatically. If testing manually, export the library paths before launching `stune`:

```bash
STUNE="$(find "$HOME/ti" -path "*/ccs_base/emulation/analysis/bin/stune/stune" -type f | head -n 1)"
STUNE_DIR="$(dirname "$STUNE")"
CCS_BASE="${STUNE_DIR%/emulation/analysis/bin/stune}"

LIB_DIRS="$(find "$CCS_BASE" -type f \( -name "libccxmlsetup.so" -o -name "libenergytracestandalone.so" \) -printf '%h\n' | sort -u | paste -sd: -)"

export LD_LIBRARY_PATH="$LIB_DIRS:$STUNE_DIR:$CCS_BASE/DebugServer/bin:$CCS_BASE/common/bin:$CCS_BASE/common/uscif:$CCS_BASE/common/uscif/xds110:${LD_LIBRARY_PATH:-}"
```

### `BAD DATA DETECTED`

This may happen when the XDS110/EnergyTrace session is left in a bad state after a previous capture.

Try:

- closing CCS debug sessions;
- closing UniFlash, SmartRF Studio, Packet Sniffer, serial monitors, and old `stune` processes;
- disconnecting and reconnecting the LaunchPad;
- using a finite capture duration before trying indefinite capture again.

### `Failed to open debug probe handle`

Typical log messages:

```text
-260 :Failed to open debug probe handle.
-261 :Failed to open debug probe handle.
-590 :Failed to open debug probe handle.
-121: Error occurred while closing debug probe port.
```

Possible causes:

- the LaunchPad/XDS110 is not connected;
- another program is using the XDS110;
- the wrong `.ccxml` target configuration is being used;
- the selected CCS/stune version wants to update XDS110 firmware;
- Linux debug probe drivers were not installed;
- WSL/USB/IP is not exposing the required probe interface;
- the XDS110 firmware is in an inconsistent state.

Try:

- closing CCS, UniFlash, SmartRF Studio, Packet Sniffer, and serial monitors;
- reconnecting the LaunchPad;
- testing `stune` manually;
- checking `lsusb` on Linux;
- running the CCS Linux driver script;
- updating or recovering XDS110 firmware with TI `xdsdfu` on Windows if needed;
- using native Windows or native Linux instead of WSL.

### Live Plot Opens but No Data Appears

Possible causes:

- `stune` did not generate a CSV;
- the wrong CSV folder or prefix was used;
- the `stune` log contains an error;
- the XDS110 is being used by another program;
- the path contains spaces and the current `stune` command handling does not support that path correctly;
- the live plot opened before the first CSV data was written.

Check the main capture log:

```text
out/YYYYMMDD_HHMMSS/log/stune_log_YYYYMMDD_HHMMSS.txt
```

### Qt Window Does Not Open on Linux

The live plot uses:

```python
matplotlib.use("QtAgg")
```

Install Qt dependencies:

```bash
pip install PyQt6
```

On Ubuntu, these system packages may also help:

```bash
sudo apt install -y \
  libxcb-cursor0 \
  libxkbcommon-x11-0 \
  libxcb-xinerama0 \
  libgl1 \
  libegl1 \
  libdbus-1-3
```

Test Qt directly:

```bash
python -c "from PyQt6.QtWidgets import QApplication, QLabel; app=QApplication([]); w=QLabel('Qt OK'); w.show(); app.exec()"
```

## Limitations

- The project depends on TI `stune`.
- EnergyTrace++ mode may not work depending on the device and target configuration.
- The sample frequency parameter is not used because some devices use a fixed EnergyTrace sampling rate.
- WSL support is experimental and may fail even when the XDS110 appears in `lsusb`.
- XDS110 firmware compatibility is controlled by the TI XDS software stack included with the selected CCS version.
- If a CCS/stune version requires an XDS110 firmware update, that update must succeed outside the Python tool.
- The live plot requires a graphical environment and the Qt backend.
